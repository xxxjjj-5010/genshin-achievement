# 原神成就统计

> 数据版本：游戏 7.0「无神怜爱的雪国」（上游 dvaJi/genshin-data release 0.62.0，2026-08-11）
> 1845 项成就 / 73 个合辑 / 14030 原石 · 纯静态站，零后端
> 支持 UIAF 一键导入 / 导出，不用再一条条手动勾
> 每个 UID 可自设密码，进度按账号独立保存

一个按 UID 分别统计原神成就进度的查漏补缺工具。数据每天自动跟上游同步，新增成就过一两天自己就长进来。

---

## 一、2026-09-18 升级：修掉一个会毁数据的隐患

原 `data.js` 停在 6.8（1759 项），且成就 key 是「文件::合辑::序号」。序号会随版本插入新成就整体后移 ——
实测直接用新数据覆盖，1759 条已保存进度里 **370 条会静默指向错误的成就**、518 条变无主数据。
（例：旧数据第 578 位的「无坚不摧」会被新的第 578 项顶替，你根本没做过却打着勾。）

**处理**：key 换成游戏内**稳定成就 id**（如 `81032`，1845 条全局唯一、不随版本变化），
并在 `data.js` 内置 `LEGACY_KEY_MAP` 迁移表，首次打开自动把旧进度转成新键、回写 localStorage，之后不再重复转换。

## 三、2026-09-21 升级（第二轮）：一键导入进度

之前最大的痛点：**游戏里完成了什么，得自己一条条对照着回来勾**，1700 多条不可能手工维护。

### 怎么解决：用社区通用的 UIAF 标准

**UIAF**（统一可交换成就格式，v1.1）是 UIGF 组织制定的成就数据交换标准（<https://uigf.org>），
椰羊、Paimon.moe、胡桃工具箱、寻空等工具都认这个格式。它的 `id` 就是**游戏内原生成就 ID** ——
而本站的 key 早在 9-18 那次重构时就已经换成了同一套编号，所以两边能直接一一对应，不需要任何映射表。

### 三步搞定

1. 用 **YaeAchievement**（开源免费的成就导出工具，Windows 专用）导出一次成就。
   官方下载（当前最新 **5.8.0**）：<https://github.com/HolographicHat/Yae/releases/latest>
   —— 项目改名成 `Yae` 了，旧地址 `.../YaeAchievement/releases` 会自动跳转，两个都能用。
   下载列表里**只拿 `YaeAchievement.exe`** 这一个（**11,234,304 字节**，约 11 MB）；
   同列表那个 `YaeAchievement.pdb` 是 **50 MB** 的调试符号文件，用不上，别下。
   ⚠️ 把 exe 放在**单独新建的文件夹**里，别和原神主程序同目录，否则游戏会报「数据异常(31-4302)」。
   然后：关掉原神 → 双击运行它 → 它会自动帮你启动游戏 → 正常登录进游戏 → 它自动读取全部成就、**读完游戏自动退出**
   （这是正常现象，不是崩溃）→ 在它给出的列表里选「UIAF JSON File」（列表最末那一项），
   得到一个 `.json`（放在 exe 同一个文件夹里，名字形如 `export-20xxxxxxxxxxxx-xxx.json`）
2. 打开本站，点顶栏「**导入进度**」
3. 选中那个 json —— 会先给你看一份报告（记录多少条、已完成多少、将新增多少），确认无误再点「确认导入」

> 💡 **站点里已经内置了这份说明**：导入弹窗里有一个「**具体操作流程**」按钮（底部也有一个同名入口），
> 点开会弹出 **7 段分步说明** —— 工具怎么下怎么用、导出选哪一项、怎么导入、多账号怎么处理、
> **常见问题排查表**、安全边界、UIAF 是什么；旁边还有一个「**下载导出工具 YaeAchievement**」直接跳转的按钮。
> （2026-09-22 精简：开头原来的「先确认你的 UID」「在本站登录」两段删掉了 —— 登录页本身就在做这两件事，
> 说明里再讲一遍是重复；后面的段号已从 1 重排。同时导入弹窗那句提示语里的「50MB 的 .pdb 别下」也去掉了。）
> 所以要把这个功能教给别人时，**让他自己点那个按钮就行**，不用你口头转述。

导入是**合并**语义：只补上你已完成、网站还没勾的，**不会取消**你已有的进度。

> ⚠️ **两个坑**
> - YaeAchievement 这类工具需要读取游戏进程内存，属于第三方软件，严格讲会碰到米哈游用户协议的边界。
>   只读、不改游戏文件，社区长期使用风险很低，但**不是零风险**，请自行判断。不想用的话，下面第二节的批量功能也能省很多事。
> - 工具的 exe **不要和原神主程序放在同一个文件夹**，否则游戏会报「数据异常(31-4302)」。放桌面新建的文件夹里就行。
> - 它抓到的数据会缓存 1 小时。**多账号**可以在缓存有效期内依次登录、分别导出，再回本站切到对应 UID 分别导入。

## 四、2026-09-21 升级：账号 + 密码锁

需求原话是：**每个 UID 自己设一个密码**，有「切换账号」和「退出登录」按钮，
而且**这个账号勾的进度，下次登录必须还在、不能被重置，各个账号之间互不影响**。

### 先讲清楚它防得住什么、防不住什么

⚠️ 这是**「本机密码锁」，不是服务器级安全**。原因很实在：本站是纯静态站，
服务器上只有几个固定文件，**没有后端也没有数据库** —— 没有地方去校验密码，也没有地方存账号。
所以密码这一层是**完全在你自己的浏览器里完成**的。

| 它能做到 | 它做不到 |
| --- | --- |
| 别人打开你这台电脑上的浏览器，**看不到也进不去**你的进度（原先是点一下 UID 就直接进） | 挡不住会按 F12 的人 —— 进度数据本身仍是明文存在浏览器里的，懂技术的人可以直接读、甚至绕过密码 |
| **防止自己手滑输错 UID**，把进度稀里糊涂写到另一个账号名下 | 换电脑 / 换浏览器 / 清缓存 → 密码和进度一起没了（因为都只存在这台设备上） |
| 密码本身**连哈希都反推不出来**：即使有人翻到存储里那串值，也拿不到你的原密码 | 当真正的账号系统用（密码忘了没有找回；也**别用你常用的重要密码**） |

**为什么不直接做成真正的服务器登录？** 那需要一个后端 + 数据库来存账号和校验，纯静态站承载不了，
而 GitHub Pages 也**跑不了任何服务端代码**。真要做 = 换掉整个托管方案，代价远大于收益。

### 密码是怎么存的（这一层是认真的）

不走「直接存密码」，也不走「存个 MD5」这类糊弄做法，而是：

```
你的密码 + 该账号专属的 16 字节随机盐
        ↓  PBKDF2-SHA256，150000 轮
存储里只留下：algo / salt / iter / hash      ← 任何一处都不出现明文
```

- **每条账号的盐都是独立随机的**：所以两个账号就算设了一模一样的密码，存进去的哈希也完全不同。
- **比对用的是哈希**：把本地存的那串哈希改掉，再输正确密码也进不去（已实测）。
- **两种运行环境结果一致**：https / localhost 下走浏览器原生 WebCrypto；
  直接用 `file://` 双击打开时浏览器不给用 WebCrypto，会自动切到本站内置的纯 JS 实现
  （同样按 RFC 标准实现，已与 Node 原生结果逐项比对通过），效果一模一样。

### 你会看到什么

| 位置 | 说明 |
| --- | --- |
| **登录页** | 新 UID → 按钮变「注册并进入」，多出一个「确认密码」框；已有密码的 UID → 按钮变「登录」，只问密码。密码框下方有强度提示（太短 / 一般 / 不错） |
| **已存过的账号** | 登录页会列出本机存过的 UID，带「已设密码 / 未设密码」小徽标。点一下只帮你**填好 UID**，不会直接进去 —— 照样得输密码 |
| **顶栏「切换账号」** | 不离开页面直接换 UID：弹窗里列出所有账号，点另一个 → 输它的密码 → 当场切过去，页面进度立刻换成那个账号的 |
| **顶栏「退出登录」** | 退出前会先把当前进度落盘，然后清除会话、回到登录页 |
| **弹窗里的「修改密码」** | 需要先输**当前密码**；改完旧密码立即失效、新密码生效（原始建号时间会保留） |
| **删除账号** | 原先点一下 × 就删了，现在**必须输对密码**才让删 |

### 几个数据安全上的关键设计

- **密码和进度分开存**：密码在 `genshin_achievement_auth_v1`，进度在 `genshin_achievements_<UID>`。
  所以**改密码、甚至删掉密码记录，都不会动到你的进度**。
- **刷新页面不掉线**：登录状态放在 `sessionStorage`，同一标签页里按 F5 不会把你踢出去；
  但**关掉浏览器再打开就要重新输密码**（会话只活在这个会话里）。
- **忘掉密码了怎么办**：站里**没有「找回密码」** —— 有找回就等于留了个后门，跟你要求的「要安全」是相抵的。
  好在密码和进度是分开存的：按 F12 → Application → Local Storage，把 `genshin_achievement_auth_v1` 里
  对应 UID 的那一项删掉，刷新页面就会回到「注册」状态，设个新密码即可，**进度一条都不会少**。
  （这也再次说明：它挡的是「顺手翻看」，不是「懂技术的人」。）

### 怎么验证「真的变了」

截图这个模型看不了，所以没法靠眼睛判断。做法是：用无头 Edge 把页面**真实渲染**，
再把结果变成**能读的文本**，分三层核对。

**第一层 —— 计算样式**：用 `--dump-dom` 导出关键元素**最终生效的** `getComputedStyle` 取值，逐项核对。实测：

- `--blue-500` 已解析为 `#c8a24a`，`--gold-500` = `#c8a24a`，`--ink-800` = `#272219` —— 变量别名这套改法生效
- `body` 背景为米白 + 三层金／青玉径向光晕，羊皮纸底纹已加载
- 法阵实测 660×660、动画 `ringSpin / 110s`；七枚纹章的颜色逐个正确
- 合辑卡片第 1～8 张的左色条依次为 **风 → 岩 → 雷 → 草 → 水 → 火 → 冰 → 风**（循环正确）
- 登录卡片四角 SVG 已加载；`.crest` 徽记 72×72 居中
- **全页扫描不到任何偏蓝的计算色** —— 旧配色没有残留

**第二层 —— 把图形变成字符画来「看」**：只盯着 SVG 路径里的数字是不放心的，
于是把 SVG 用无头 Edge 渲染成位图，再按明暗把像素采样成 ASCII 字符画，肉眼确认形状确实是
「漩涡 / 菱形编织 / 圆弧闪电 / 植株 / 水滴 / 火焰 / 雪花」，并确认 `<use>` 引用能真的画出图形。
**这一层是专门为「符号画错了」这个问题加的** —— 不靠印象，直接看渲染结果。

同时跑了功能回归：**137 项断言全部通过、运行时错误 0 条**，改视觉没有碰坏任何功能。

## 七、为什么已保存的进度不会丢

- 进度**按 UID 分键独立存储**（`genshin_achievements_<UID>`），两个账号之间互不覆盖、互不可见。
- 成就 key 用游戏内稳定 id，上游怎么增删改名都不影响已有勾选。
- `data.js` 带 1759 条旧键 → 新 id 的完整迁移表；首次进入某个 UID 时自动转换并回写。
- 迁移保真度已**全量实测**：1759 条旧键全部落到存在的成就上，其中 1758 条名称完全一致，
  唯一不同的「QUEST FAILED」是上游自己把它改成了「QUEST FAILED  OR …」（描述也从「跟丢了悬赏目标…」扩充为整句），
  新数据里没有任何名字叫 `QUEST FAILED` 的条目，确认映射正确。
- 设密码、改密码、退出登录都不会清进度：**密码是另一套键，和进度完全解耦**。
- 另建议养成习惯：**每次版本更新后用「导出备份（JSON）」或「导出 UIAF」存一份**。
  备份可原样导入（导入是合并，不覆盖）；UIAF 还能带着进度迁移到别的成就工具。
  —— **这两个导出也是你唯一的「云端」**，因为密码和进度都只存在浏览器里，换个环境就都没了。

## 八、需要长期维护的只有一处

`app.js` 顶部的 `BLOCKED` 名单 —— 当前版本暂时拿不到的成就。它们会被标黄并从完成度分母里排除。
现在有 3 条：`苍明如冰`（至冬七天神像满级）、`「影域老司机」`（影域解析等级满级）、`伟业的遂成`（同时持有 22 种月谕圣牌）。
每次版本更新后复核一次（游戏里点一下就知道能不能拿）。**所以主进度显示的分母是 1842，不是 1845。**

版本中文名不用手动维护了：`tools/build-data.mjs` 里的 `VERSION_NAMES` 已收录 7.0 / 7.1，
新版本想显示中文名在那里补一行即可，没补就沿用上一版名称。

## 九、数据是怎么自动跟版的

```
dvaJi/genshin-data（上游，版本更新后 1 天内同步）
        ↓  每天北京时间 10:00 / 也可在 Actions 页手动触发
tools/build-data.mjs
        ↓  ① 拉取 73 个合辑 JSON
        ↓  ② 重建 data.js（key 用稳定 id）
        ↓  ③ 标记新成就的版本号（对比 6.8 基线 + 上一版 data.js 的 v 字段）
        ↓  ④ 内容没变就退出，不产生提交
GitHub Actions 提交 data.js → GitHub Pages 自动部署
```

生成器的三个细节：

- **版本标记自给自足**：不用额外的基线文件。基线 = `LEGACY_KEY_MAP` 的 1759 个 id，
  上一版的 `v` 字段直接从 `data.js` 里读回来，既不在基线、上一版也没记录的 id 才算本次新增。
  实测模拟 7.1 到来时，新增的只会被标成 7.1，已有的 86 条 7.0 标记不会被打乱。
- **多源降级**：文件内容按 `raw.githubusercontent.com` → `cdn.jsdelivr.net` → GitHub API 依次尝试。
  某些网络环境（含本机代理）会拦 `raw` 域名，多一路备用可以少一次「同步失败」。首次成功的源会被记住，后续直接用。
- **8 路并发下载**：73 个合辑并行拉取，实测本机 57 秒跑完（网络好时更快）。

## 十一、要注意的架构边界

- **是纯静态站**：服务器上只有 4 个固定文件，没有后端和数据库。所有「动」的部分（渲染、搜索、筛选、算完成度、**密码校验**）都在你的浏览器里跑。
- **进度和密码都只存在这台设备的这个浏览器里**：按 UID 分键存在 localStorage。换电脑、换浏览器、清缓存 = 两者一起归零，
  服务器端根本不知道你是谁、做到哪了，也不知道你设过密码。所以「导出备份（JSON）」/「导出 UIAF」是你唯一的云端，建议每个版本更新后存一次。
  （UIAF 导入导出全程在你的浏览器里完成，**文件不会上传到任何服务器**。）
- **密码这一层同理**：它是在浏览器里「自己校验自己」，因此**防的是顺手翻看，不防专业绕过**。
  别把它当银行密码用，也别拿你在别处用过的密码来设 —— 这一点在登录页的安全说明里也原样写了。
- 每天自动更新只是把 `data.js` 这个静态文件换成新版再重新部署 —— 相当于每天出一版新报纸，不是开了个直播间。
